# The `.otd` project format

`.otd` is RON, it is text, and it is meant to be read in a diff. Never put an
API key in one — see `docs/AI.md`.

## Shape

```ron
(
  format: "opentouchdesigner-project",
  version: 1,
  fps: 60.0,
  nodes: [
    (
      path: "/noise1",
      op: "noiseTOP",
      pos: (-200.0, 0.0),
      params: {
        "period": (value: Float(0.25)),
      },
    ),
    (
      path: "/out1",
      op: "nullTOP",
      pos: (40.0, 0.0),
      inputs: ["/noise1"],
    ),
  ],
)
```

- `path` is absolute and unique. `/name` at the top level, `/comp/name` inside
  a Container COMP.
- `op` is a type name from the registry — `noiseTOP`, `lagCHOP`,
  `geometryCOMP`, `scriptDAT`. `docs/OPERATORS.md` is the whole list, generated
  from the registry, so it cannot drift.
- `inputs` is positional: element 0 is in0, element 1 is in1.
- `pos` is canvas coordinates. Lay a chain out left to right, ~180 apart, and
  branches on separate rows — a patch nobody can read is a patch nobody edits.
- `params` omits anything left at its default. Don't write defaults back out.

## Parameter values

`value:` is typed and the type must match what the operator declares:
`Float`, `Int`, `Bool`, `Str`, `Vec2`, `Vec3`, `Vec4`. Vectors are tuples:
`Vec3((0.0, 1.0, 0.0))`.

## The four parameter modes

```ron
"period":    (value: Float(0.25)),                                   // Constant (default, omit `mode`)
"translate": (value: Vec3((0.0,0.0,0.0)), mode: Expression,
              expression: "absTime * 0.05"),
"period":    (value: Float(0.25), mode: Export, source: "/bass:bass"),  // op_path:channel
"hue":       (value: Float(0.0),  mode: Bind,   source: "/master:hue"), // op_path:param
```

Expressions see `absTime`, `time`, `frame`, `fps`, `me`, the `math` names
(`sin`, `cos`, `sqrt`, `pi`, …) and `clamp` / `fit` / `lerp` / `smoothstep`.
Reach into the network with `ch('/op', 'chan')`, `par('/op', 'name')` and
`parent('name')`. See the `otd-python` skill.

An expression on a vector parameter returns a list: `"[0.0, absTime * 12.0, 0.0]"`.

## Working on a patch

```bash
otd docs --out docs/OPERATORS.md      # regenerate the reference from the registry
otd demo tunnel --out /tmp/t.otd      # the shipped examples are generated, not hand-saved
otd run patch.otd --frames 120        # cook headlessly; DMX/OSC outputs still send
otd render patch.otd --node /out1 --frames 60 --out /tmp/frames
otd stats patch.otd --frames 300      # per-node timings
otd bundle patch.otd --out /tmp/show  # project + every media file it references
```

`cargo run -p otd-cli --` in place of `otd` when working from the checkout.

## Checks that catch the usual mistakes

- Cook it. `otd run patch.otd --frames 2` fails loudly on an unknown op type,
  a dangling input path, or a parameter type mismatch.
- Render one frame and look at it before claiming a patch works.
- A patch whose output is black almost always has nothing flagged for render
  and no `--node` — name the terminal node explicitly.

## Editing the shipped examples

`examples/*.otd` are generated by `otd demo`, from `crates/otd-engine/src/demo.rs`.
Change the demo, then regenerate — hand-editing the example leaves the two
describing different patches.
